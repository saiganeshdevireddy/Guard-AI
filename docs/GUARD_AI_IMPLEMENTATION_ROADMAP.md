# Guard AI Implementation Roadmap

**Status:** proposed sequence. All new controls and browser runtime components are unimplemented unless identified as existing in repository documentation. Hosting and privacy decisions remain pending user approval. The canonical architecture and matrix are in [GUARD_AI_MASTER_ARCHITECTURE.md](GUARD_AI_MASTER_ARCHITECTURE.md), browser details in [ISOLATED_BROWSER_ARCHITECTURE.md](ISOLATED_BROWSER_ARCHITECTURE.md), and risks in [SECURITY_AUDIT_FINDINGS.md](SECURITY_AUDIT_FINDINGS.md).

## Required architecture decisions

The current implementation has five primary agents and Wi-Fi as a Finder specialized agent. The target has six; any source-code promotion needs separate authorization and must preserve current analysis. Defence owns browser/security policy and retains vault/Cryptographic Maze responsibilities. Session Manager, Worker Supervisor, Egress Gateway, Display Gateway and Cleanup Manager execute under that policy. Transmitter, Transformer and Rollback remain preserved concepts with target interfaces in the master matrix; implementation-level schemas, operational runbooks and named operators remain pending. Local blockchain hash anchoring is not a complete Transformer. Hosting, topology, privacy, budget, concurrency, authorization and Android scope remain pending. See [master architecture](GUARD_AI_MASTER_ARCHITECTURE.md) and [browser MVP plan](BROWSER_RUNTIME_MVP_IMPLEMENTATION_PLAN.md).
