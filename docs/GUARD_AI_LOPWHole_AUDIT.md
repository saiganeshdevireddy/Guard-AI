# Guard AI Loophole Audit

**Status:** design-time risk register based on repository review and proposed architecture. No runtime penetration or security test was performed. “Mitigation” below is a requirement, not evidence it is active.

This is a compact audit summary. Use the canonical [SECURITY_AUDIT_FINDINGS.md](SECURITY_AUDIT_FINDINGS.md) for current finding status, fallback and validation crosswalk; ownership decisions are in [GUARD_AI_MASTER_ARCHITECTURE.md](GUARD_AI_MASTER_ARCHITECTURE.md).

| Risk / threat | Impact | Required prevention and detection | Fallback / recovery | Residual risk / validation |
|---|---|---|---|---|
| Confused deputy or privilege drift across six agents | Unauthorized actions | PDP, distinct identities, typed scopes, independent API authorization, deny by default; audit every decision | Deny action, revoke identity, safe mode | Control-plane compromise remains; test role matrix and forged sender |
| Prompt injection via web/file content | Agent instruction execution | Treat all content as data; isolate parsers; schema allowlist; no tool authority in content | Drop/quarantine payload, notify user | Novel parser/model behavior; adversarial content tests |
| Finder heuristic treated as safety guarantee | User exposure or auto-browse | Display uncertainty; require explicit user action; no auto-launch | Stop/revoke session | False negatives remain; test score boundary and UI language |
| SSRF, private IP, cloud metadata, IPv6 | Internal service/credential access | Gateway resolves and filters all A/AAAA addresses at connect time; block special ranges and metadata; repeat after redirects | Drop connection and fence guest | DNS/proxy implementation defects; test mixed answers and mapped IPv6 |
| DNS rebinding, redirect, alternate proxy, QUIC/tunnel bypass | Egress policy bypass | Gateway-only route, controlled DNS, proxy enforcement, block direct UDP/DoH/QUIC and unapproved protocols | Host firewall denies egress | Permitted destinations can still host harmful content; packet-level bypass tests |
| Host/LAN/control-plane access | Lateral movement | Separate networks, no host routes, ingress allowlist, host firewall | Isolate worker and revoke session | Misconfiguration/host compromise; route and packet tests |
| Cross-user/session leakage | Data disclosure or control | One VM/profile per session; unique storage/network/display identity; ownership checks | Revoke capabilities, destroy affected sessions | Hypervisor shared-resource side channels; cross-session tests |
| Capability theft, replay, confused audience | Session hijack | Short expiry, one-time nonce, audience/scope/session/user binding, rotation, revocation, rate limit | Revoke and terminate | Client compromise; replay and stolen-token tests |
| Browser/guest escape or VM escape | Worker compromise | Minimal signed image, patched hypervisor/jailer, no shared mounts/devices, syscall/resource confinement | Fence host, stop worker, incident response | Zero-days and host compromise remain; escape-resilience assessment |
| Remote display/input abuse | Hijack, clipboard exfiltration, unsafe input | Separate service; ticket validation; origin/CSRF controls; bounded input; disable clipboard/files/devices/debug | Revoke stream and stop session | Browser/client vulnerabilities; ticket replay and input fuzzing |
| Disk/profile/download remnants | Cross-session disclosure | Ephemeral encrypted overlays, isolated temporary storage, deterministic teardown, cleanup verification | Quarantine worker; block reuse; operator recovery | SSD/cloud snapshot erasure limits; forensic remanence tests |
| Secret/log leakage | Credential exposure | Secret manager, redaction, structured allowlist events, no contents/keystrokes/screenshots | Revoke/rotate secrets, restrict logs | Debug traces and crash dumps; canary-secret scan |
| Worker/gateway restart or lost network | Orphan VM or egress leak | Persistent default-deny host firewall, independent watchdog, authenticated readiness and reconciliation | Fence sessions; deny launch; reconcile owned resources | Partition delays cleanup; fault injection |
| Resource exhaustion / denial of service | Service outage or cost spike | Admission control, CPU/RAM/disk/network/duration limits, quotas, bounded queues and alerts | Reject new sessions; stop abusive/stale sessions | Shared host contention; saturation/load tests |
| Control-plane compromise | Attacker creates sessions or abuses worker | Narrow worker API, independent worker-side policy, explicit intent, MFA/admin separation, egress limits, audit | Revoke control identity; safe mode; isolate worker | Authorized but malicious commands may remain; tabletop and compromise tests |
| Supply-chain or image compromise | Persistent guest/host compromise | Pinned dependencies, signed/provenanced images, review, staged rollout and revocation | Roll back to verified image; quarantine | Signing pipeline compromise; provenance verification drills |
| In-process event bus loss/failure | Missed lifecycle events | Do not use as sole durable workflow; idempotent durable state and watchdog | Reconcile from worker inventory | Database/worker split-brain; crash/restart tests |
| Privacy overcollection / inappropriate reporting | User harm and legal exposure | Minimize telemetry; retention approval; Informer user-only; explicit consent before external sharing | Stop collection, delete per policy, incident review | Jurisdiction-dependent requirements remain unresolved |

Existing source-specific issue: the local event bus stores recent full payloads in memory and has no message authentication, schema enforcement, durable delivery or independent watchdog. Current code must not be mistaken for the proposed protocol.
